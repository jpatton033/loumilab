- Loumilab Local listings live in merchant_local_profiles and may exist without a storefront (Local-only merchant = merchants row, no storefront); public reads go only through security-definer RPCs search_local_businesses/get_local_business — keeps Local free of the Orders onboarding while exposing safe fields only.
- Local Importer: unclaimed listings are merchant_local_profiles rows with merchant_id NULL and ownership_status 'unclaimed'; staging lives in staff-only local_* tables and publishing/claims/suppression go only through security-definer RPCs (publish_local_candidate, decide_local_claim, decide_local_request, suppress_local_profile) — keeps one canonical listing and makes approval the only path to public.
- Local Importer extraction runs only through the staff-only `local-import-run` edge function (Firecrawl via gateway), reading approved domains only and writing to candidates/evidence, never publishing — keeps approval the only path to public.
- Anonymous Local listing submissions go only through the `submit_local_listing` RPC into `local_candidates` (source_type visitor) for staff review; sign-in is required only to claim — keeps approval the only path to public.
- Admin people/merchant directory data (account email, verification, last sign-in) comes only through the staff-gated `admin_merchant_directory` RPC — auth tables are never exposed to the client.
- Human photography sections use the shared brand PhotoSplit component and .photo-frame utility; card hover uses .glow-hover — keeps imagery and interaction consistent across Loumilab products.

- Visual breaks (immersive image, statement, sequence, transition, editorial) use the shared components in src/components/brand/story — keeps the storytelling language consistent site-wide.
- Homepage product/grid tiles use the shared components in src/components/brand/apple/Tiles.tsx — keeps the Apple-style homepage consistent.
- Per-page SEO (title, description, canonical, og/twitter, WebPage + BreadcrumbList JSON-LD) goes only through SEOHead props; article overrides live on kc_articles SEO columns with automatic fallbacks — one place for head tags.
- Raw-HTML SEO for public routes comes from scripts/prerender-heads.ts (postbuild), which writes dist/<route>/index.html with per-route head tags and an sr-only H1; add new public routes to its staticMeta and to generate-sitemap — crawlers that skip JS otherwise see only the homepage head.
- Header logo motion is an optional `Wordmark` state that plays once per browser session and respects reduced motion — keeps the canonical logo reusable and avoids a loading-screen dependency.
- The brand dot motion system lives in src/components/brand/dot (shared tokens in tokens.ts): calm ease-out, no bounce, no full-screen fills or scale bursts, small movements, scroll-triggered once, at most three moments per page, never replacing ordinary punctuation — keeps the dot present but quiet.
- The Dot. issue emails go only through the admin-only `dot-issue-blast` function (Resend), claimed once per issue via `dot_issues.emailed_at` — prevents duplicate blasts and keeps newsletter mail off the transactional sender.
- The Dot. editorial sections reuse MailEditor; content_format explicitly separates legacy plain text from sanitized rich HTML, and dot_issue_templates stores admin-only content without issue/send metadata — preserves legacy rendering and keeps templates from triggering broadcasts.
- The Dot. rich HTML runs through an editor-typography CSS allowlist before HTML sanitization; never allow unfiltered inline styles — preserves writing tools without enabling arbitrary CSS.
- Ad conversion tracking (Meta Pixel, Google tag) goes only through src/lib/tracking (`track()`), loads only when an ID is set there and ad consent allows (regional banner via /cdn-cgi/trace, EEA/UK/CH), and never sends customer identifiers — one consent gate and one event map for every ad platform.
- Website traffic for the ops brief comes only from first-party anonymous page views via the `record_page_view` RPC into staff-read `site_page_views` (no IP/identity; admin, login and preview hosts skipped) — keeps analytics free of external APIs and personal data.
- Orders setup uses numbered, non-scrolling mobile progress and locally expanded touch targets with existing UI controls — keeps every step discoverable without changing shared controls or store-saving behavior.
- Platform-fee promotions live in orders_promotions (staff-only) with per-merchant snapshotted terms in merchant_promotions (one per account); qualification runs only in DB triggers via promo_qualify, and the fee is lowered only in _shared/fees.ts through the pure promoFee.ts rule (min of plan and promo, 0–10%) — keeps promos tamper-proof and unable to stack or raise fees.
